# 既知の制限事項

## レイアウト推定の限界

Harunobu は IslandDetector によるヒューリスティックなレイアウト推定を行い、Excel/CSV ファイル内のテーブル領域を自動検出します。以下のケースで精度が低下することがあります。

- 複雑なレイアウト: 入れ子表（表の中に表がある構造）や複合ヘッダー（複数行にまたがるヘッダー）では、テーブル境界の推定精度が低下します
- 空白行・列が多いデータ: データ領域内に意図的な空白行・列がある場合、1つのテーブルが複数に分断されて検出されることがあります
- 表の前のタイトル行: テーブルの直前にタイトル行がある場合、タイトル行がテーブル外（`sheet_others`）として分離され、L1-04（データ範囲外情報チェック）で違反として報告されます。これは仕様通りの動作ですが、タイトルや出典注釈を持つ行政データでは意図的な配置であることが多いです
- 横並びの複数テーブル: 同一行に複数のテーブルが横並びに配置されている場合、正しく分離できないことがあります

## 判定対象外のルール

以下のルールは現在 `confidence=0` で常にパスを返します（スキップ扱い）。スコアには影響しません。

| ルールID | ルール名 | 理由 |
|---------|---------|------|
| L3-02 | 回答のコード表が別添されているか | コード表の有無をファイル単体で自動判定することが困難なため対象外 |
| L3-03 | 特殊記号の定義を明記しているか | 凡例や注記の自動検出精度が低いため対象外 |
| L3-07 | 年によってフォーマットが著しく異なっていないか | 単一ファイル評価では判定不可。複数ファイル一括アップロード時のみ `check_bulk` で評価します |
| L3-08 | データの定義や更新履歴が記載されているか | メタデータ記述の自動検出精度が低いため対象外 |

## ルールごとの既知の制限

### L1-08 機種依存文字チェック

ファイルのエンコーディングによって判定が異なります。

- Shift-JIS（CP932）で読み込まれた場合: 丸数字・ローマ数字等の警告対象文字を含む場合は `passed=False`（NG）
- UTF-8 / xlsx の場合: 同じ文字を検出しても `passed=True`（参考報告のみ）。Unicode コードポイントが一意のため互換性リスクが低いと判断します。

全角英数字（Ａ、１等）はエンコーディングによらず `info` レベルの参考報告として検出されますが、NG 判定の対象外です。

### L1-10 オブジェクト検出

OOXML の `drawing*.xml` を直接解析して検出します（対象: 画像 `pic`、グラフ `graphicFrame`、図形 `sp`、コネクタ `cxnSp`）。OOXML の読み取りに失敗した場合、または `object_refs` が未ロードの場合は `confidence=0.0` で判定不能（abstain）として扱います。

テキストボックスも `sp` 要素として検出対象に含まれます。ただし、オブジェクトのアンカー位置（起点セル）での判定のため、表の範囲内にアンカーがあれば違反として検出します。

### L1-11 書式ベースの意味表現

決定論的チェック（フォント色・背景色・太字・斜体の複数使用検出）は AI の有無にかかわらず動作します。AI（AIVisualAnalyzer + LibreOffice）が有効な場合は、Excel の画像から書式による意味付けをより正確に確認する補完チェックを実行します。AI が無効な場合は、決定論的チェックのみで判定します。

### L2-02 項目名の省略

「同」「〃」等の省略記号や空白行による省略は決定論的に検出します。「H28」「R3」等の和暦略称や文脈依存の省略（前行の値を暗黙的に繰り返す形式）は AI（AISemanticChecker）が有効な場合のみ検出します。

### L2-06 数式の値変換

OOXML の `formula_refs` が正常にロードされていない場合（パース失敗等）は `confidence=0.0` で判定不能として扱います。OOXML 解析に成功している場合は、表の範囲内の全数式セルと数式エラーセルを検出します。

### L3-05 時間軸の標準化

和暦略称（R5、H30 等）および元号フル表記（令和5年、平成30年度等）はパターンマッチで検出します。ISO 8601（`YYYY-MM-DD`）、JIS X 0301 和暦短縮形（`R8.05.13`）、e-Stat 形式（`YYYY年M月`、`YYYY/M/D`）、年度表記（`YYYY年度`）は標準表記として許容します。

非標準的な2桁年表記（`03/04/01` 等の曖昧な日付）や元号+数字のみ（`令和3` 等、「年」なし）は違反として検出します。

### L3-06 地域コード

標準地域コードマスタ（JIS X 0401/0402）との照合で都道府県・市区町村の検出を行います。マスタに含まれない独自コードや、地域名称の表記揺れ（例: 「東京」と「東京都」）には対応に限界があります。AI（AISemanticChecker）が有効な場合は、曖昧なヘッダー名で地域データが隠れている可能性を追加チェックします。

## ルール正本と実装の差分

ルールの正本（「行政データにおける機械可読性に関するルール」）は自然言語で記述されており、Harunobu ではこれを機械的な判定ロジックに近似変換しています。以下に主な近似判定の例を示します。

### L1-04「無関係な情報」

- 正本の定義: データ本体と無関係な情報がないか
- 実装: レイアウト推定の `sheet_others`（タイトル・注釈・出典・合計などテーブル外として分離されたセル）が非空なら違反とする
- 近似の限界: 意味的に「無関係」かどうかの判定は行わず、テーブル外に配置されている時点で違反扱いとする厳しい判定を行っています。タイトル・末尾注釈・出典なども `region_type` にかかわらず NG となるため、それらを許容したい場合は別シートに分離するなどデータ構造を改める必要があります

### L1-05「意味が推測できる項目名」

- 正本の定義: すべての列に意味が推測できる項目名が存在するか
- 実装: ヘッダー欠落検出・連番数値ヘッダー検出（決定論的）+ ビジュアル分析による構造問題の補完検出（AIVisualAnalyzer）
- 近似の限界: 人間にとっての「意味が推測できる」を完全に再現することはできません。また、ドメイン固有の専門用語の適切さまでは判定できません

### L2-04「選択肢の標準化」

- 正本の定義: 選択肢回答が標準化されているか
- 実装: 出現頻度の少ない外れ値をパターン検出（決定論的）+「男」「男性」「M」等の意味的な表記ゆれを検出（AISemanticChecker）
- 近似の限界: ドメイン知識なしでの近似判定です。確信が低いケースはAIも見逃す方向（誤検出より見逃しを優先）で設計されています

正本テキストの全文は [https://www.cas.go.jp/jp/seisaku/digital_gyozaikaikaku/pdf/gyouseidata_rule.pdf](https://www.cas.go.jp/jp/seisaku/digital_gyozaikaikaku/pdf/gyouseidata_rule.pdf) を参照してください。

## 誤検知しやすいケース

以下のケースでは、実際には問題がないにもかかわらず違反として検出されることがあります（偽陽性）。

- タイトル行・出典注釈を持つファイル: テーブル前後のタイトル行や注釈セルが `sheet_others` として分離され、L1-04（データ範囲外情報チェック）で違反として報告されます。行政データでは出典注釈・凡例注記が一般的なため発生しやすい誤検知です
- 意図的な空白行を含む集計表: 小計行や区切り行として空白行を意図的に挿入している場合、L1-03（データ分断チェック）で違反として検出されます
- 「その他（〇〇）」形式の正当な値: L2-05（その他詳細分離）は「その他」と詳細が混在するパターンを検出しますが、列名として自然な「その他（施設管理費）」等を誤検知することがあります。AI有効時は誤検知が減少します
- 「人口」以外でゼロが自然に発生する列の空白: L1-09（空白・ゼロ区別チェック）は AI が「ゼロが発生しにくい」と判断した列のみを違反とするため、AI の信頼度次第で誤検知が生じる場合があります
- 住所列以外の全角スペースの意図的使用: L1-06（体裁用スペース・改行チェック）では住所系カラムの全角スペースは除外されます。また、リストマーカー（ア、イ、ウ...）や注釈（※1 等）の後の全角スペースもセマンティック使用として除外されますが、パターン外の正当な全角スペースは誤検知されることがあります

## 見逃しやすいケース

以下のケースでは、実際に問題があるにもかかわらず検出されないことがあります（偽陰性）。

- 書式のみで区別された情報（AI 無効時）: AI が無効な環境では、色・太字等の書式による意味付け（L1-11）の検出はフォント色・背景色・太字・斜体の複数使用という決定論的な手がかりのみに限定されます。LibreOffice が未インストールの場合は AIVisualAnalyzer による補完が動作しません
- 複数テーブルが同一行に横並び: 横並びのテーブルが1つのテーブルとして誤認識され、L1-02（1シート1表チェック）の違反を検出できないことがあります
- 文脈依存の省略パターン（AI 無効時）: 「同上」「〃」以外の、文脈に依存する暗黙的な省略（前行と同じ値の省略等）は AI が無効な場合に検出されません
- コード表・メタデータの不備: L3-02（コード表の別添）、L3-03（特殊記号の定義）、L3-08（メタデータ記載）は判定対象外としているため、これらに関する問題は一切検出されません
- フォーマット一貫性の問題（単一ファイル時）: L3-07（年によるフォーマット変動）は複数ファイルを一括アップロードした場合のみ評価されます。単一ファイルでは常にパスとなります
- ゼロと空白の意図的な混在: L1-09（空白・ゼロ区別チェック）は AI が有効な場合のみ動作します。AI が無効な場合は confidence=0 でスキップされるため、この問題は検出されません
- OOXML が正常に読み取れないファイルのオブジェクト・数式: L1-10（オブジェクトチェック）および L2-06（数式の値変換）は OOXML 解析に失敗した場合に confidence=0 で判定不能となるため、問題があっても見逃します
